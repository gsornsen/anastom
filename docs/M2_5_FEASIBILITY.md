# M2.5 Claude Code feasibility — design-stage evidence

Status: **complete model-free and synthetic-native implementation audit.** [ADR 0015](adr/0015-claude-code-worker-profile.md) records the owner-accepted design and implementation refinements. The separate provider-backed Task and durable acceptance results are recorded in [M2.5 evidence](M2_5_EVIDENCE.md).

## Official interface and authentication findings

- Anthropic documents `claude -p` as a programmatic interface with JSON/JSONL output and schema-constrained final output. [Programmatic guide](https://code.claude.com/docs/en/headless), [CLI reference](https://code.claude.com/docs/en/cli-usage).
- `--bare` skips normal OAuth/keychain credentials and requires API credentials; `--safe-mode` preserves authentication but disables ordinary customizations. Administrator-managed policy still applies. [Programmatic guide](https://code.claude.com/docs/en/headless), [CLI reference](https://code.claude.com/docs/en/cli-usage), [settings precedence](https://code.claude.com/docs/en/configuration).
- The Agent SDK overview says third-party products need prior approval to offer claude.ai login or rate limits. The more specific Claude Code legal guide allows end users to sign in to an unmodified binary with their own subscription, including when hosted, but forbids third-party login flows, credential routing on users' behalf, token intermediation, and resale. The June 15, 2026 Agent SDK credit change was paused; the current help-center notice says existing SDK, `claude -p`, and third-party subscription usage continues under subscription limits. These sources support considering a local-direct, end-user-authenticated CLI mode while leaving the "on behalf of" automation interpretation for review. [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk), [legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), [pause notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan).
- Print mode can select an ambient `ANTHROPIC_API_KEY` ahead of a subscription login. Explicit source selection and source checking are needed to prevent silent API billing. [Authentication](https://code.claude.com/docs/en/team).
- Managed policy outranks CLI flags; server-managed settings can apply from cache or refresh after startup. Teams/Enterprise are eligible for server delivery; Pro/Max personal plans are not. Endpoint-managed files and macOS managed preferences remain possible regardless of subscription tier. Print mode silently applies managed hooks without an approval dialog, so an ordinary loopback test cannot close that gate. [Configuration](https://code.claude.com/docs/en/configuration), [server-managed settings](https://code.claude.com/docs/en/server-managed-settings).

These are source findings and a reviewed design inference, not a blanket legal determination. Anastom implements explicit subscription and API-key selections using each end user's separately installed CLI. The owner accepted the local-direct boundary and its remaining automation ambiguity in ADR 0015.

## Exact local audit

On 2026-09-15 the owner's macOS arm64 native Claude Code CLI reported `2.1.268 (Claude Code)` and resolved to `~/.local/share/claude/versions/2.1.268`, a 193 MiB Mach-O binary. The local binary SHA-256 was `06a96d5423f83770f120859f1c58e60d7252cc4c122aa13043b7e7cd716bc76a`. The official npm package `@anthropic-ai/claude-code@2.1.268` exists; the [setup guide](https://code.claude.com/docs/en/setup) says its platform package installs the same native binary. The exact npm metadata archive SHA-512 was `0d24545406d1447ed66879bdf4e12b4f814940391b84851bf2621a7af705ad7b4a099c00f5498a639f923855a6832784523d94875a45c34464fe061f7e650453` and matched registry `dist.integrity`. Anthropic also publishes a signed [release manifest](https://code.claude.com/docs/en/setup) for the native installer. The pinned manifest and detached signature were downloaded separately, the signing key fingerprint matched the documented `31DDDE24DDFAB679F42D7BD2BAA929FF1A7ECACE`, GPG reported a good signature, and its `darwin-arm64` SHA-256 matched this installed native binary exactly. This closes the owner-platform binary provenance slice without bundling Anthropic's proprietary executable. The archive's `LICENSE.md` declares use subject to Anthropic's [legal agreements](https://code.claude.com/docs/en/legal-and-compliance), not AGPL; Anastom must not relabel or bundle that executable as AGPL code. After the owner authenticated Claude Code separately, `claude auth status --json` reported `loggedIn:true`, `authMethod:claude.ai`, `apiProvider:firstParty`, and `subscriptionType:max`. Only those allowlisted fields are relevant to this audit; no account identity, organization metadata, OAuth/keychain value, or API key was opened or recorded. Pi's Anthropic login is separate.

The checked-in [probe](../scripts/probe-claude-cli.ts) creates an isolated temporary workspace/configuration and a local HTTP endpoint. It passes only a synthetic API key and loopback `ANTHROPIC_BASE_URL` to the CLI; it does not use the owner's normal authentication or a real provider. It invokes the constant `claude` command from PATH and checks the exact reported version. PATH provenance and the executable/platform-package match remain separate pre-live gates; this design fixture does not attest them. Run it with the official CLI installed on PATH:

pnpm exec tsx scripts/probe-claude-cli.ts --stream-json

Both local model requests named the synthetic selection `claude-sonnet-4-6`, carried one user message and four tools (`Glob`, `Grep`, `Read`, `StructuredOutput`), included a schema output configuration, contained the fixture prompt, and omitted `AMBIENT_SENTINEL`. ## Source-adapter native checks after design acceptance

The new [adapter package](../packages/runtime-claude-code/README.md) never searches PATH for a release binary. Its model-free `capabilities()` resolves the official native-installer `2.1.268` file in the operator's home directory, rejects a symlink/nonexecutable file or mismatched SHA-256, and compares bytes with the separately verified signed manifest hashes for Linux/macOS arm64/x64. It checks the selected authentication source and managed-policy evidence before creating run state; `start()` repeats preflight for each attempt. On the owner macOS arm64 installation, [the opt-in preflight](../scripts/probe-claude-preflight.ts) returned `subscription-source-confirmed`, `absent-by-conservative-gate`, both filesystem workspace modes, native structured output, and `modelCalls:0`. Its login-form check accepted only `loggedIn:true`, `authMethod:claude.ai`, `apiProvider:firstParty`, and a personal Pro/Max plan. It discarded the account and organization fields in native status JSON. An injected ambient API key rejects subscription mode before that status command; API-key mode requires an environment key and uses Anthropic's documented `--bare` mode, which never reads OAuth/keychain credentials. Synthetic auth doubles prove wrong-login rejection and API-key mode's absence of an auth-status fallback.

The owner machine's unrestricted `profiles status` saw eight generic macOS configuration profiles, while the filesystem sandbox reported zero. The fail-closed gate was tested in the unrestricted environment. It rejects any Claude Code endpoint-managed system file, any matching file in `/Library/Managed Preferences`, or an effective `com.anthropic.claudecode` preferences domain. It also rejects unreadable/unrecognized OS inventory. The owner machine's domain/file checks found no Claude Code policy and admitted the personal Max login; generic unrelated profiles did not suffice to reject it. macOS `profiles show -all` requires root, so the gate relies on the effective preference-domain query and file inventory rather than a full profile-payload dump. The owner reviewed that conservative interpretation before the live call; possible policy delivery between preflight and spawn remains a documented limit. A personal Max plan excludes Anthropic's documented Team/Enterprise-only remote settings delivery; API bare mode does not use a Claude.ai organization login. Synthetic managed-hook/tool/instruction files and unavailable inventory are rejected before model execution.

The opt-in [production-profile localhost probe](../scripts/probe-claude-adapter.ts) invokes the attested native binary through the actual adapter arguments, but injects only a synthetic key and loopback HTTP endpoint. The subscription-shaped run used `--safe-mode --restricted`, returned a schema-valid StructuredOutput, and excluded planted user/project CLAUDE.md, custom skill, custom agent, project SessionStart hook, and private sentinel from the model-visible request/public events. Its request exposed `Edit`, `Glob`, `Grep`, `Read`, `Write`, and `StructuredOutput`, with no MCP/plugin entry. It made two identical-looking fake message POSTs for a direct structured response and four for a file-tool turn; why the CLI duplicates the messages remains unknown. `--max-turns` is not a request or billing cap.

Seven synthetic subscription file-tool cases passed: Read/Write inside the assigned workspace worked; outside and symlink-escape reads/writes did not access or modify the target; and a protected `.claude/settings.json` write left that file unchanged. The API-key `--bare --restricted` run returned a valid report but exposed only `Read`, `Edit`, and `StructuredOutput` despite requesting a larger tool set. Four synthetic API Edit cases showed an existing workspace file could be edited, while outside, symlink-escape, and protected settings targets stayed unchanged. The implementation therefore narrows the API-key tool allowlist to Read/Edit and does not claim new-file creation for that mode. These fake responses are deterministic protocol probes, not model-quality evidence or real subscription/API billing proof.

Shared runtime conformance and separate process doubles cover schema-valid/invalid/missing reports, native failure, split multibyte and oversized/premature JSONL, public queue pressure, partial split-input usage, configured/reported identity, private sentinel exclusion, request snapshots, and terminal-result immutability. On macOS outside the filesystem sandbox, process tests confirmed cleanup before success, cancellation during initialization/execution, TERM-resistant leader and descendant, surviving descendant, blocked late write, concurrent attempts, and zombie-only group treatment. Linux CI remains a required platform check. Result-level Anthropic usage is mapped to inclusive input plus cache-read/cache-write and output with partial coverage; the fake repeated requests show why it cannot be treated as complete billing evidence. The original unchanged M2 Task, later-process durable inspection, and provider-backed run remain completion gates in the [build brief](M2_5_BUILD_BRIEF.md).

The stricter synthetic probe now derives read observations only from actual `tool_result` blocks. An inside-workspace Read returned its sentinel there; outside and symlink reads did not. A native HTTP 400 fixture became a sanitized `model-provider` failure with one fake POST. A malformed synthetic `StructuredOutput` produced ten fake POSTs and ended as a native `model-provider` failure without a private response body in public events. The reason for those repeated requests is not established. The pinned native binary's invalid-report path differs from the deterministic process double's direct schema-violation path, so both are recorded without conflating them.

[ADR 0016](adr/0016-path-policy-after-third-adapter.md) compares the path use cases after this third adapter. It proposes no generic path helper in M2.5; Fake scenario file references and verifier working directories are candidates for a small later extraction because their canonical-root and internal-symlink rules match. Executable provenance, managed-policy discovery, native model file tools, auth-store linking, and immutable artifacts do not share that contract.

Its official package archive had SHA-512 `058f8e8f31da9fc2ca74a37ac96e1ffea9ea5a50453b52c779b6da031101f48183825375a6f5374318cf18036edb409a52dea51e3ebb382efd67bb4c2de2acd1`; base64 matched registry `dist.integrity` exactly. Inspection occurred in `/private/tmp` without installing a project dependency or running the SDK. Published declarations expose a custom `spawnClaudeCodeProcess` seam, `AbortController`, `Query.close()`, structured output, and an alpha `resolveSettings()` that does not execute `policyHelper` or fetch fresh server-managed settings by itself.
