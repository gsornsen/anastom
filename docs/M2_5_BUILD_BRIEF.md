**Accepted for implementation by the owner on 2026-09-15 under [issue #13](https://github.com/gsornsen/anastom/issues/13).** M2 is complete and remains the compatibility baseline. [ADR 0015](adr/0015-claude-code-worker-profile.md) records the reviewed CLI decision; [design-stage feasibility](M2_5_FEASIBILITY.md) records official sources and a synthetic native probe. Execute the same strict Markdown Task through one explicitly selected Claude Code worker. Preserve Anastom's capability preflight, immutable context, bounded lifecycle, engine-validated report, independent command verifier, durable event/artifact history, and later-process inspection. ## Adapter and control-plane contract

Add `packages/runtime-claude-code` behind the existing `RuntimeAdapter` interface. Its `capabilities()` is model-free, returns only validated enabled behavior, and rejects missing exact installation or mismatched explicitly selected authentication before a run is created. At minimum it must declare the selected `readonly`/`isolated` workspace mode, cancellation, structured output, and available telemetry truthfully. Unknown capabilities remain unknown. `start()` snapshots the immutable request; every attempt launches a fresh process/session with only agent work and no previous conversation or failed-attempt text. The engine validates final JSON against `requiredOutputSchema` and runs the verifier independently. No native success field may bypass engine acceptance.

The adapter must own and confirm the whole process group through success, failure, cancellation, timeout, and startup errors. Termination uncertainty is a failure that prevents retry. Bound stdout JSONL frames, stderr bytes, event queue pressure, and total attempts; whitelist only public observations. Native tool commands, thinking, transcripts, credential metadata, debug data, and raw errors do not enter public events. Record configured/reported identity provenance and runtime version. Map only documented token counters, account for Anthropic's split uncached/cache-read/cache-write inputs when producing Anastom's inclusive input total, and keep missing/ambiguous counters absent. Coverage is partial when calls are not completely observed. Usage cannot decide success, billing, or cost routing.

Use current shared conformance support in `packages/runtime-contract/src/testing/` with a deterministic Claude Code process double and real-native synthetic loopback tests. Public contract changes require versioned schema validation, focused reducer/replay tests, documentation, and an explicit compatibility decision. Keep original Pi/Codex/fake behavior and M1/M2 durable rows readable unchanged; do not add SQLite tables or rewrite applied migrations for this adapter. No model or credentials enter routine tests/CI.

## Native feasibility gates before live use

1. Verify the end user's separately installed, unmodified official CLI/native package version and platform binary, matching exact package provenance and official integrity; reject unverified PATH substitution or version drift. Do not redistribute the proprietary binary under Anastom's AGPL license. Record executable hash and environment without credential values.
2. Prove the chosen `--safe-mode --restricted` profile suppresses ordinary CLAUDE.md, skills, hooks, plugins, MCP, memory, and custom agents; demonstrate allowed read/write file tools inside the workspace and rejection of paths outside it, symlink escapes, and protected state. A fixture must show the model-visible request shape without printing private prompts.
3. Establish effective managed-policy behavior with a model-free interface or a reviewed conservative rejection gate. Test conflicting managed instructions/tools/hooks and unavailable policy evidence before any live provider call. An ordinary synthetic loopback base URL is insufficient because it bypasses remote managed settings.
4. Establish explicit authentication-source precedence from official interface behavior and whitelisted `claude auth status` metadata. API-key mode must not become a subscription login, and subscription mode must reject an ambient API key that would silently take precedence. Prove the local-direct profile keeps sign-in in Anthropic's unmodified CLI and Anastom does not intermediate tokens or requests. Review the remaining "on behalf of" interpretation against [Anthropic's legal guidance](https://code.claude.com/docs/en/legal-and-compliance); seek clarification if it cannot be resolved for the distributed adapter. No copied OAuth/keychain credentials or keyring probing.
5. Prove schema-valid final `StructuredOutput`, invalid/missing output, native nonzero exit, premature EOF, split/multibyte/oversized JSONL, hidden retry/compaction observations, partial usage, identity provenance, and private sentinel exclusion. Keep `--max-turns` separate from model-request and Task duration bounds.
6. Prove confirmed process-group cleanup, cancellation during initialization and execution, SIGTERM resistance, descendants, late writes, concurrent attempts, and terminal-result immutability on Linux and macOS. If the CLI/SDK cannot satisfy this, revise ADR 0015 before a live call.

The design-stage [loopback probe](M2_5_FEASIBILITY.md) closes only a narrow structured-output/ordinary-ambient slice of these gates. It does not establish direct subscription execution or authentication-source verification, managed-policy isolation, file mutation, usage accounting, or process cleanup.

## Portability demonstration and completion evidence

After design approval and all native gates, run the unchanged dependency-free endpoint Task from M2 in a fresh clone at the same baseline commit and Task-byte digest, selecting `--runtime claude-code --provider anthropic --model <owner-selected-model>` and the approved authentication source. A live execution must be explicitly approved by the owner after the feasibility evidence is reviewable. The independent two-test HTTP verifier must pass with exit zero, the source checkout stay clean, and the isolated worktree/diff remain available. The run must replay through later-process `status` and `inspect --json` with no Claude Code executable or provider authentication. Verify all referenced artifact digests independently and compare the durable common contract with M2 Pi/Codex evidence without claiming comparative model quality.

`M2_5_EVIDENCE.md` must record accepted design/implementation commit identities; exact package/native versions and environment; authentication/legal boundary and selected source without secrets; each native gate and its result; shared conformance and platform process tests; required suite/types/lint/format/hygiene/API docs/CodeQL/DCO/dependency checks; the live run ID, Task/base digests, verifier output, later-process inspection, public capability/identity/usage observations with unknowns; worktree/source/artifact integrity; original M1/M2 store replay; and the path-policy decision informed by this adapter. Update root README/changelog, affected package README/changelog, and a reviewed SemVer Changeset for actual package/API changes.

M2.5 remains one selected worker and one independent verifier. Exclude automatic routing/fallback, crash recovery, multiple workers, cost budgets, cloud/UI surfaces, and Mycelium migration features. Owner review of the implementation PR and every listed evidence item is the completion gate.
